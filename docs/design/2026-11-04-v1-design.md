## 1. Stack

**Choice: Astro (static output) + a TypeScript spec-check CLI + GitHub Actions + Cloudflare Pages (free).**

- Astro emits plain HTML and ships no client JS by default. A gallery is a set of static pages over files in git, so there is no runtime to pay for or secure.
- Content lives in git as files (§2). Astro reads the already-validated catalogue at build time.
- Cloudflare Pages Free hosts it. It does not charge for bandwidth on static assets, which matters because every download is a file of up to 1 MB. Previews are noindex by default, which gives us a launch gate for free (§3.8).
- No database. Content is fewer than a few hundred curated files, changed by PR review, never by users. Postgres would add a service, a bill and a migration path for zero queries. Azure is unnecessary for the same reason. Revisit only if uploads/accounts arrive.

**Expected monthly cost: $0** (Cloudflare Pages Free + GitHub Actions on a public repo, free for public repos). The only likely cost is a custom domain, which is optional and not priced here (registrar dependent; Kai to decide, OQ3).

**Rejected alternative: Vercel Hobby (Next.js or Astro).** Also $0, but (a) Hobby is "for personal, non-commercial use", so ads or sponsorship later forces Pro at $20/mo per seat; (b) 100 GB/mo transfer cap, about 100k max-size downloads, and Hobby cannot buy more usage; (c) password protection for a gated preview is Pro-only plus $20/project/mo. All from https://vercel.com/pricing. Cloudflare has lower cost risk on the one thing this site does a lot: serving PNGs.

Also rejected: Git LFS for PNGs. It adds a quota and a hosting-integration step for no gain at our size (see §2.3).

## 2. Module layout and data model

### 2.1 Tree

```
tesla-wrap-workshop/
├─ content/
│  └─ wraps/
│     └─ <wrap-id>/               # one folder per wrap; id = folder name
│        ├─ meta.json             # WrapMeta (validated)
│        └─ <file-name>.png       # the exact file users download; name is Tesla-legal
├─ src/
│  ├─ domain/                     # pure, no Astro, no fs
│  │  ├─ variants.ts              # VARIANTS registry (closed enum + dims + template URL)
│  │  ├─ licences.ts              # LICENCES registry (allowlist + required provenance)
│  │  ├─ wrap.ts                  # WrapMeta schema (zod) + Wrap type
│  │  └─ spec.ts                  # checkPng(bytes, name, variant) -> Violation[]
│  ├─ catalogue/
│  │  └─ load.ts                  # THE boundary: fs -> parse -> validate -> Catalogue | Violation[]
│  ├─ guards/                     # repo-wide checks, each a pure fn over a file list
│  │  ├─ brand.ts                 # font/asset/word denylist
│  │  ├─ no-rehost.ts             # sha256 + name denylist of Tesla files
│  │  └─ links.ts                 # outbound template links must hit teslamotors/custom-wraps
│  ├─ site/                       # Astro: pages/, components/, layouts/ (no validation here)
│  │  ├─ pages/index.astro, wraps/[id].astro, models/[variant].astro, about.astro
│  │  └─ components/Disclaimer.astro, WrapCard.astro, TemplateLink.astro
│  └─ cli/
│     └─ check.ts                 # `npm run check`: runs catalogue + guards, prints report
├─ scripts/post-build/            # checks over dist/: disclaimer, links, budget, gate
├─ guards/
│  ├─ tesla-template-sha256.txt   # hashes only, never the files
│  └─ brand-denylist.json
├─ .github/workflows/ci.yml
├─ .github/pull_request_template.md   # human review checklist (logos, characters, provenance)
└─ astro.config.mjs, package.json, tsconfig.json
```

Ownership is by domain (variants, licences, wrap spec, catalogue), not by phase. Astro pages only render a `Catalogue`; they never re-check files.

```ts
// src/domain/licences.ts — allowlist; provenance requirements live with the licence
type Provenance =
  | { kind: "own"; author: string; createdWith?: string }                // our design
  | { kind: "third-party"; author: string; sourceUrl: string;             // CC0 / PD input art
      sourceLicenceUrl: string; retrievedOn: string /* YYYY-MM-DD */ };

export const LICENCES = {
  "CC-BY-4.0": { url: "https://creativecommons.org/licenses/by/4.0/", allows: ["own"] },
  "CC0-1.0":   { url: "https://creativecommons.org/publicdomain/zero/1.0/", allows: ["own", "third-party"] },
  "PD":        { url: null,                                           allows: ["third-party"] },
} as const;
export type LicenceId = keyof typeof LICENCES;
```

```ts
// src/domain/wrap.ts — on-disk shape (meta.json), validated once in catalogue/load.ts
export type WrapMeta = {
  id: string;              // == folder name, /^[a-z0-9-]{3,40}$/
  title: string;           // display title, 1..80 chars
  variant: VariantId;      // closed enum
  file: string;            // PNG filename in the folder; Tesla-legal (see spec)
  licence: LicenceId;
  provenance: Provenance[];// >=1; each entry's kind must be allowed by `licence`
  tags: string[];          // lowercase slugs, <=8
  addedOn: string;         // YYYY-MM-DD
};

// derived at load time from the PNG bytes — never hand-written, so it can't drift
export type Wrap = WrapMeta & { width: number; height: number; bytes: number; sha256: string };
export type Catalogue = { wraps: readonly Wrap[]; byVariant: ReadonlyMap<VariantId, readonly Wrap[]> };
```

`width/height/bytes/sha256` are derived, not stored. Storing them would create a second source of truth that CI must keep in sync.

```ts
// src/domain/spec.ts — pure
export const SPEC = {
  maxBytes: 1_000_000,                         // conservative: "1 MB" undefined (REPORT §3)
  fileName: /^[A-Za-z0-9_\- ]{1,26}\.png$/,    // whole name incl. ".png" <= 30 (conservative)
  pngMagic: [0x89,0x50,0x4e,0x47,0x0d,0x0a,0x1a,0x0a],
  minSide: 512, maxSide: 1024,
} as const;

export type Violation =
  | { code: "not-png" } | { code: "bad-name"; name: string }
  | { code: "too-big"; bytes: number }
  | { code: "wrong-dims"; got: [number, number]; want: [number, number] }
  | { code: "schema"; path: string; msg: string }
  | { code: "licence-provenance"; licence: LicenceId; kind: string }
  | { code: "dup-sha"; sha256: string; ids: string[] }
  | { code: "id-mismatch"; folder: string; id: string };

export declare function checkPng(bytes: Uint8Array, name: string, v: VariantId): Violation[];
// dims read from the IHDR chunk (bytes 16..23); no image library needed for the check.

// src/catalogue/load.ts — the only place raw files become typed data
export declare function loadCatalogue(root: string):
  Promise<{ ok: true; catalogue: Catalogue } | { ok: false; violations: (Violation & { wrap: string })[] }>;
```

Dimension rule: a wrap must equal its variant's template size exactly (1024x1024, Cybertruck 1024x768). That is stricter than Tesla's 512–1024 range and matches "use template size". It also makes the Cybertruck non-square case explicit instead of special-cased.

### 2.3 Storage: plain git, no LFS

One folder per wrap, PNG committed directly. Each PNG is capped at 1,000,000 bytes, so 200 wraps cost at most about 200 MB of history; realistically half that after oxipng. That is fine for a normal GitHub repo and avoids LFS quotas and Pages LFS build setup. Rule: replacing a PNG needs a new id. That keeps history growth to one copy per wrap. Re-evaluate at 300 wraps (OQ4).

## 3. Guards (all run by `npm run check` locally and in CI on every PR)

| # | Guard | Where | Fails when |
|---|---|---|---|
| G1 | Spec-check | `catalogue/load.ts` → `spec.ts` | not PNG magic; dims ≠ variant template; bytes > 1,000,000; filename fails regex |
| G2 | Metadata schema | same boundary (zod) | meta.json missing/invalid; unknown variant; `id` ≠ folder; `file` missing |
| G3 | Licence allowlist | same | licence not in `LICENCES`; provenance kind not allowed; third-party entry missing url/licence/date |
| G4 | Duplicate sha | same | two wraps have identical sha256 |
| G5 | No rehost | `guards/no-rehost.ts` | any repo file's sha256 is in `tesla-template-sha256.txt` (the 12 template.png + 12 vehicle_image.png + examples, hashed once from Tesla's repo; hashes only), or any file is named `template.png` / `vehicle_image.png` |
| G6 | Brand lint | `guards/brand.ts` | grep hits in src/ or dist/ for font names (`Gotham`, `Tesla T`, `TESLA` wordmark font files), font files not on an allowlist, assets named `*tesla*logo*`, SVG `<path>` matching the stored T-logo path data |
| G7 | Logo-in-image (substitute) | PR template + G5 | Honest limit: detecting a Tesla logo drawn into a PNG is not feasible reliably in v1. Substitutes: (a) mandatory PR checklist "no Tesla/third-party logos, marks, characters", signed by reviewer; (b) G5's exact-hash denylist; (c) perceptual-hash near-match against Tesla example wraps, listed as a later issue only if needed |
| G8 | Disclaimer present | `scripts/post-build` | any `dist/**/*.html` lacks `data-testid="disclaimer"` with text "not affiliated with Tesla" |
| G9 | Template links | `scripts/post-build` | an outbound link labelled as a template doesn't start with `https://github.com/teslamotors/custom-wraps/`; or any `<a>`/`<img>` points at `raw.githubusercontent.com/teslamotors` (hotlinking = rehost-by-proxy) |
| G10 | Size budget | `scripts/post-build` | any HTML page > 50 KB; total JS > 20 KB; per-page thumbnails > 600 KB (thumbnails are build-generated WebP, not the source PNG) |
| G11 | Launch gate | `scripts/post-build` | `PUBLIC_LAUNCH` ≠ `true` and any page lacks `<meta name="robots" content="noindex,nofollow">` or robots.txt lacks `Disallow: /` |

### 3.8 Launch gate choice

**Pick: production branch = `release`, which doesn't exist until launch, plus a build flag `PUBLIC_LAUNCH` defaulting to false.** Until legal sign-off, `main` deploys only as a Cloudflare Pages preview (`*.pages.dev`, noindex header by default) with an Access policy on previews, and every page also carries noindex meta + `Disallow: /` (G11). Launch = create `release` from `main`, set `PUBLIC_LAUNCH=true` on the production environment, and add the domain.

Why: it costs $0, needs no code (unlike a password page in a static site, which is not real protection), and the "go public" act is one reviewable change that can't happen by accident on a normal merge. Rejected: password protection (Vercel Pro cost; DIY JS password is fake). Rejected: noindex alone (still public and linkable).

## 4. v1 issues (do in order; each is green before the next starts)

Common: Node 22, `npm ci` first. "Expected" is the last line(s) of output.

### I1. Scaffold + domain types + spec-check + one sample wrap (end to end)
- Goal: a repo that builds and validates one real wrap locally.
- Acceptance: Astro static project; `src/domain/{variants,licences,wrap,spec}.ts` as §2.2; `src/catalogue/load.ts`; `npm run check` runs G1–G4; one own wrap `content/wraps/sample-solid-grey/` for `model3` (1024x1024, CC0-1.0, own provenance), filename `Solid Grey.png`; index page lists it; unit tests for `checkPng` with fixtures: valid, 1,000,001 bytes, 1023x1024, JPEG renamed .png, 27-char stem, Cybertruck 1024x1024 (must fail).
- Out of scope: styling, other guards, CI, deploy.
- Done: `npm ci && npm test && npm run check && npm run build` → `check: 1 wrap, 0 violations` and Astro `Complete!`; then `cp test/fixtures/too-big.png content/wraps/sample-solid-grey/"Solid Grey.png" && npm run check; echo $?` → `too-big ... sample-solid-grey` and `1` (restore with `git checkout content`).

### I2. CI workflow
- Goal: every PR runs the same checks as local.
- Acceptance: `.github/workflows/ci.yml` runs `npm ci, npm test, npm run check, npm run build, npm run postbuild:check` on PR and push to main. Required status check on `main`.
- Out of scope: deploy.
- Done: `npx --yes @action-validator/cli .github/workflows/ci.yml && echo ok` → `ok`; and `gh run list --workflow ci.yml --limit 1 --json conclusion -q '.[0].conclusion'` → `success`.

### I3. Gallery pages
- Goal: browse by variant and download.
- Acceptance: `/`, `/models/<variant>/` for all 12, `/wraps/<id>/` showing title, variant, dims, bytes, licence + link, author/provenance, tags, and a download link to the exact PNG with `download="<file>"`. Thumbnails built as WebP. Empty variants show "no wraps yet" plus the template link.
- Out of scope: search, 3D preview, filters beyond variant.
- Done: `npm run build && ls dist/models | wc -l && test -f "dist/wraps/sample-solid-grey/Solid Grey.png" && echo dl-ok` → `12` and `dl-ok`.

### I4. Template links + G9 link check
- Goal: every variant page links to Tesla's template folder; nothing hotlinks Tesla files.
- Acceptance: `TemplateLink.astro` uses `templateUrl(v)` only; post-build G9; `lychee` (or equivalent) verifies the 12 URLs return 200 in a weekly scheduled job, not per PR (avoids flaky PRs).
- Out of scope: mirroring templates.
- Done: `npm run build && npm run postbuild:check -- --only links` → `links: 12 template links ok, 0 tesla hotlinks`.

### I5. Disclaimer + G8
- Goal: "Not affiliated with, endorsed by or sponsored by Tesla, Inc." on every page footer plus an /about page.
- Acceptance: component in base layout; post-build G8.
- Out of scope: legal wording sign-off (that is I10).
- Done: `npm run build && npm run postbuild:check -- --only disclaimer` → `disclaimer: N/N pages ok` (N = page count).

### I6. No-rehost guard (G5)
- Goal: CI fails if any Tesla template/example file is committed.
- Acceptance: `scripts/hash-tesla-files` (one-off, run by a human, prints hashes to stdout; never writes PNGs to the repo) produces `guards/tesla-template-sha256.txt`; `npm run check` applies G5 to all tracked files.
- Out of scope: perceptual hashing.
- Done: `curl -sLo /tmp/t/template.png --create-dirs https://raw.githubusercontent.com/teslamotors/custom-wraps/master/model3/template.png && cp /tmp/t/template.png content/x.png && npm run check; echo $?; rm content/x.png` → `no-rehost: content/x.png matches tesla model3/template.png` and `1`.

### I7. Brand lint (G6) + PR checklist (G7)
- Goal: block Tesla fonts/logos in code and assets; make the human check explicit.
- Acceptance: `guards/brand-denylist.json` (font names, filename patterns, T-logo SVG path signature); scan src/, public/, dist/; system font stack only; PR template checklist.
- Out of scope: image logo detection.
- Done: `echo "font-family: Gotham" > src/site/x.css && npm run check; echo $?; rm src/site/x.css` → `brand: src/site/x.css font "Gotham" denied` and `1`.

### I8. Size budget (G10)
- Goal: pages stay small.
- Acceptance: budgets in §3 enforced post-build; report prints the largest page.
- Out of scope: Lighthouse.
- Done: `npm run build && npm run postbuild:check -- --only budget` → `budget: ok (max html <50KB, js <20KB)`.

### I9. Deploy behind the launch gate (G11)
- Goal: a working gated preview on Cloudflare Pages.
- Acceptance: Pages project linked to repo, production branch = `release` (not created), `PUBLIC_LAUNCH` unset; Access policy on previews; G11 in post-build.
- Out of scope: custom domain, going public.
- Done: `curl -sI https://main.<project>.pages.dev | grep -i -E 'x-robots-tag|location|HTTP/'` → `x-robots-tag: noindex` or a 302 to Access login; and `npm run build && grep -c 'noindex,nofollow' dist/index.html` → `1`.

### I10. Seed content + in-car smoke test
- Goal: launch-worthy set of own designs, one per variant where we can test.
- Acceptance: ≥1 own wrap per variant (12+), all G1–G7 green; in-car test log in `docs/in-car-tests.md` for at least Model 3/Y/Cybertruck, including a boundary file (999,9xx bytes, 30-char name) to settle REPORT open Q5.
- Out of scope: third-party art unless CC0/PD with provenance.
- Done: `npm run check` → `check: 12+ wraps, 0 violations`; `grep -c '| pass |' docs/in-car-tests.md` → `≥3`.

### I11. Legal review packet
- Goal: give Kai/counsel everything needed to sign off.
- Acceptance: `docs/legal-review.md`: name/domain, disclaimer text, list of wraps with licence + provenance (generated from catalogue), UV-template derivative question (REPORT §5), preview URL; a `LEGAL_SIGNOFF` line left blank for Kai.
- Out of scope: legal advice; changing content based on it (new issues).
- Done: `npm run legal:packet && grep -c '^| ' docs/legal-review.md` → wrap count + 1; `grep '^LEGAL_SIGNOFF:' docs/legal-review.md` → `LEGAL_SIGNOFF:` (empty).

### I12. Public launch — BLOCKED on Kai's legal sign-off
