# Catalogue architecture A: incremental hardening

Goal: make the curated Tesla Paint Shop gallery enforce its documented local requirements while retaining its existing static build, human content review, and separate legal and release gates. This is a design report, not an implementation or legal sign-off.

Base SHA: `943b3f679613853f3cf4f1590fbf2a491d0a1039`. The working tree also contained pre-existing modifications to `package.json` and untracked `.agents/`, `.audit/`, and `scripts/verify-provenance.ts`. The observations include that working tree; no other files were changed by this investigation. The report does not establish the current Tesla requirements remotely. It follows the recorded research and conservative repository decisions, which should be checked against Tesla before release.

## How it works

`content/wraps/<id>/meta.json` and its named PNG enter through `loadCatalogue(root)` in `src/catalogue/load.ts`. Zod and `checkProvenance` in `src/domain/wrap.ts` validate the metadata and licence combination; `src/domain/spec.ts` checks signature, IHDR dimensions, filename, and byte count; the loader hashes bytes and rejects duplicates. It returns either a sorted `Catalogue` indexed by all 12 variants or a list of wrap-scoped violations. `src/cli/check.ts` formats these. Each Astro page loads the catalogue, and `astro.config.mjs` loads it again in `astro:build:done`, copies source PNGs unchanged to the download path, and uses sharp for 512px WebP thumbnails. `scripts/verify-gallery.ts` checks generated pages, downloads against source bytes, and thumbnail metadata. `scripts/check-links.ts` parses built HTML, requires exactly the registered template link on each model page, and checks selected links for Tesla raw hotlinks. `scripts/postbuild-check.ts` currently dispatches only links. `.github/workflows/ci.yml` runs the existing commands and only the links postbuild gate.

Repository decisions permit own designs and third-party CC0/PD sources subject to provenance, CC0-1.0 and CC-BY-4.0 output licences, and links to Tesla templates rather than hosting them (`docs/decisions.md`, `docs/design/2026-11-04-v1-design.md` sections 2-4). `PD` is not an output licence; source public-domain evidence belongs in third-party provenance. The sample is one own wrap; 12 seed designs and actual in-car tests remain a human/content dependency. Exact dimensions and 1,000,000-byte and 30-character limits are intentionally conservative project policy, not proof Tesla defines its ambiguous boundaries that way. The Cybertruck template is 1024x768 in the recorded measurements.

## Evidence-backed gaps

1. `src/domain/spec.ts:43` accepts a 24-byte prefix as a valid PNG if magic, IHDR marker and dimensions match. Read-only probe: `checkPng(readFileSync('test/fixtures/valid.png').subarray(0,24), 'wrap.png', 'model3')` returned `[]`. `src/catalogue/load.ts:75` consequently admits it; `npm run check` can pass corrupt download content even if a later sharp thumbnail operation fails. Header-only tests in `test/check-png.test.ts` do not cover full file integrity.
2. `src/domain/wrap.ts:7`, `:31-37`, `:48-56`, and `:81-95` accept non-URL third-party sources, impossible dates and whitespace-only titles. A read-only probe with `sourceUrl: 'javascript:alert(1)'`, `sourceLicenceUrl: 'bad'`, `retrievedOn` and `addedOn` both `2026-99-99`, and `title: ' '` passed both schema and provenance checks. `src/site/pages/wraps/[id].astro` renders these source strings into links. Treat untrusted URLs as an output safety concern as well as a provenance quality gap. `scripts/verify-provenance.ts` is pre-existing untracked work and currently treats impossible dates as valid; coordinate any change with its owner.
3. `src/catalogue/load.ts:66-73` reads `meta.file` before its filename is checked. An invalid relative filename can cause an out-of-folder read before `bad-name` is returned; symlinks can similarly lead the loader or copier outside the content root. Validate filename before filesystem access and reject symlinks, with explicit failure rather than silently skipping them. Hash and decode the same bytes that are eventually copied, or explicitly recheck source hash at copy to close the build-time time-of-check/time-of-use gap.
4. I5-I9 are not implemented as documented: `Base.astro` has no disclaimer or robots meta; no about page exists; postbuild dispatcher supports only links; the CI invocation uses `--only links`. No committed brand/no-rehost guards or review checklist are present. Existing G9 checks are scoped to selected HTML elements and raw.githubusercontent.com Tesla paths; they do not establish that no Tesla assets are served via CSS, other hosts, or files in the repo. Avoid claiming a comprehensive ban on all Tesla imagery from this check.
5. No legal packet generator or sign-off exists. Local noindex directives are indexing hints, not access controls. Preview Access policy and production branch state must be verified in Cloudflare separately, and I12 remains gated by Kai's legal sign-off (`docs/decisions.md`).

## Chosen design and boundaries

### PNG and metadata

Keep the existing synchronous, pure `checkPng(bytes, name, variant): Violation[]` as a fast header/spec check. Add an async IO-boundary helper, e.g. `verifyPngIntegrity(bytes: Buffer): Promise<IntegrityFinding[]>`, called once by `loadCatalogue` only after name, size, magic and dimension checks pass. Use the existing sharp dependency for a full pixel decode, not `sharp(...).metadata()` alone, with strict error handling and bounded input pixels. In addition, validate PNG chunk structure, lengths, CRCs, IHDR ordering, at least one IDAT, IEND and no trailing payload; test strict decoder behavior with mutated CRC, truncated IDAT, missing IEND and malformed compressed data. A successful header or metadata read alone is not integrity proof. Return a stable `invalid-png` violation, not raw native error strings. Cap bytes and expected dimensions before decode. Preserve source bytes and hashes; never re-encode download PNGs or strip metadata silently.

Before `readFile`, reject invalid basename via `SPEC.fileName`, use `lstat` and reject symlinks for both wrap directory and file, and require a regular file. Gather independent metadata and filename diagnostics where practical but never read the bad path. Avoid following symlinks in scanner traversals. Build copy should verify the bytes read still have the catalogue hash before writing, and use those bytes for thumbnail generation as well. The current concurrent mutation model is not guaranteed atomic; do not promise more without a snapshot contract.

In `wrap.ts` add reusable nonblank text, strict calendar-date and absolute HTTP(S) URL refinements. Keep licence/provenance policy centralized there, and retain the current discriminated union and outward `licence-provenance` result where compatibility matters. Check `addedOn` and `retrievedOn` as actual dates (round-trip UTC or equivalent), reject unsafe schemes and malformed/empty URLs. Validate source licence claims as a human-review matter, not merely by URL syntax. Keep CC0-only third-party sources and CC-BY own-only policy as decided. Surface source author, source URL, licence URL, retrieval date and optional creation details on the detail page and legal packet. Adjust existing provenance verifier expectations if the owner agrees, preserving its useful coverage.

Alternative: use sharp directly inside `checkPng`, making it async and coupling pure domain code to native IO-like decoding. Rejected because it changes every existing caller and obscures the boundary. Sharp metadata alone is cheaper but does not force decompression or prove integrity. A bespoke full PNG decoder is unnecessary and riskier than bounded structural checks plus the existing decoder.

### Repository guards

Add narrow `scripts/check-no-rehost.ts` and `scripts/check-brand.ts`, invoked by `npm run check` alongside catalogue check; keep `loadCatalogue` usable without scanning the repo. Expose functions that return deterministic findings, for example `checkNoRehost(root: string, manifest: HashManifest): Promise<GuardFinding[]>` and `checkBrand(roots: readonly string[], policy: BrandPolicy): Promise<GuardFinding[]>`. CLI aggregates all findings and exits nonzero; IO and malformed/missing manifest errors fail closed. Include tracked and untracked nonignored files in the working tree so the design's `content/x.png` probe is caught; distinguish repo-wide file coverage from generated `dist` coverage and ignore `.git`, dependencies and build output in repo scan. Independently scan generated `dist` after build. Explicitly reject symlinks or inspect their safe targets with a documented rule. Do not scan outside the root.

Generate a versioned manifest containing source URL, pinned upstream commit, relative source path and SHA-256 for every template, vehicle image and example file, including nested example directories. A human-run updater fetches to temporary storage, computes hashes and removes temp files; never check in upstream PNGs. Fail closed on empty or malformed manifest, compare hashes regardless of filename, and also reject exact `template.png` and `vehicle_image.png` basenames case-insensitively. Exact hashes cannot detect modified images; manual PR review remains mandatory. Supply tests using synthetic local fixture hashes rather than copyrighted Tesla fixtures. Record coverage and update date; a pinned manifest only covers the upstream snapshot, not future Tesla changes.

Brand policy should enumerate disallowed Tesla font names and logo asset patterns, restrict bundled font files to the chosen system-font policy, and match a documented T-logo SVG path signature. Scan source/public and rendered output, with parser-aware or narrow file-content checks and deterministic path reporting. Text-only matching and exact SVG path signatures cannot recognize visually altered logos or marks inside PNGs. Add `.github/pull_request_template.md` for reviewer attestation of logos, characters, provenance and no Tesla files; do not present it as automated proof.

### Postbuild and launch

Extend `scripts/postbuild-check.ts` dispatch to `links | disclaimer | budget | launch`, defaulting to all checks and rejecting invalid `--only` values. Small named helpers can share one strict `dist` HTML walker and parse5, keeping existing link semantics. CI must run the default full command, not `--only links`.

`Base.astro` should render the exact I5 disclaimer in a visible footer and `/about/` should explain independence and link to official templates. On every generated HTML page the disclaimer check should find visible text within the footer, not merely a hidden marker or comment. The budget check must fail missing dist or malformed HTML and report the largest page: HTML per page <= 50 KB, aggregate emitted JS <= 20 KB, and sum of local thumbnail bytes actually referenced by each page <= 600 KB. Define inclusive decimal bytes explicitly and deduplicate repeated identical image references on a page; parse URL paths safely and reject missing/escaping targets. Keep these guard limits distinct from Tesla's image limit.

Default `PUBLIC_LAUNCH` to false. For a private build, put `noindex,nofollow` in each HTML head and `User-agent: *\nDisallow: /` in robots.txt. Launch mode should require an explicit `PUBLIC_LAUNCH=true` and separately check the sign-off/release procedure; do not turn a nonempty string into verified legal approval. Check both inverse states and missing/conflicting tags. A local build flag and robots cannot enforce privacy: Cloudflare Access and release branch setup require operator verification and are not implied by successful local tests. Do not deploy or set the flag as part of the local backlog.

### Legal packet

`npm run legal:packet` should load the validated catalogue and generate deterministic Markdown with name, actual preview URL or explicit `not configured`, disclaimer, catalogue rows (id, variant, output licence and all provenance), the UV-derivative question, and `LEGAL_SIGNOFF:` blank. Escape Markdown table cells and avoid exposing private URLs or inventing a preview. Separate generated inventory from counsel's answers and preserve existing sign-off/manual sections; fail if regeneration would overwrite a nonempty sign-off instead of silently erasing or fabricating it. Sign-off remains an explicit Kai action. Legal packet is a review aid, not legal advice or authorization to launch.

## Incremental verification

1. Fix input boundary first. Test valid real PNGs and each corruption class through `loadCatalogue` and CLI, and test output hashes and exact original downloads. Add path traversal, symlink, invalid URL, impossible date, whitespace title and valid CC0/CC-BY cases. Check all current fixtures; any header-only fixtures may need real valid images. Run `npm test`, `npm run check`, `npm run build` and `npm run verify:gallery`.
2. Add no-rehost and brand guard fixtures for renamed exact copies, forbidden basenames, nested untracked files, safe files, paths/symlinks and the documented exclusions; test default CLI and postbuild paths. Validate manifest coverage against the pinned upstream file inventory. A real Tesla-file probe belongs in disposable temp storage, never the repository.
3. Add disclaimer, about, budgets and both local gate modes. Test missing/hidden disclaimer, missing pages, boundary and over-budget HTML/JS/thumb sums, bad local URLs, absent/conflicting robots controls, and full dispatch. Run a full static build and inspect actual output. Keep privacy verification separate.
4. Generate packet from both own and third-party fixtures, assert all provenance fields and table escaping, empty initial sign-off, deterministic regeneration, and preservation/fail-closed behavior for an existing sign-off. Then run the full CI command sequence.
5. Seed designs, actual Model 3/Y/Cybertruck in-car evidence, current Tesla requirements, private Cloudflare Access, counsel review and Kai's legal/release sign-off remain external work; local passing tests do not complete them.

## Tradeoffs and residual risk

This design preserves the existing catalogue result type and existing consumers, adding only one native dependency already installed and focused script helpers. It does not introduce a plugin framework, database, runtime service or a second source of catalogue truth. It assumes repository authors can change files during a build; hash checks detect changes at read time but cannot make a mutable checkout atomic. Exact hash and path checks do not prove rights, image originality or brand compliance; human review and counsel remain necessary. Manifest provenance and inventory completeness are required before describing no-rehost as covering Tesla's known snapshot. The design is an independent sequential exploration, not a multi-model architectural review.
